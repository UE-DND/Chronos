# ADR 0043：主题配色与宿主插件契约

- 日期：2026-09-20

2026-11-13 修订：插件实例、存储、日历贡献及公共界面的当前契约见 [ADR 0052](0052-plugin-activation-and-calendar-contributions.md)。本记录保留原决策的背景；与后续契约冲突的接口不再适用。

## 主题职责

M3 的算法、颜色、课程调色板和资源生成都由 `theme-m3` 负责。插件交付静态颜色 JSON 和 ESM。ESM 注册主题，也可以提供 `resolveWallpaperColors({ pixels, mode, signal })`。主题只计算颜色。图片的保存、解码、降采样、取消、结果校验和 DOM 更新都由宿主做。颜色键和 Tailwind 的对应关系是公共契约，宿主不留一套 M3 备用色表。

只有 Profile 的默认主题支持取色，并且壁纸来源是 `custom` 时，才从壁纸取色。没有图片，或者取色失败，就用这个主题本来的外观，不关掉用户的偏好。只有条件不再成立时才关闭取色。主题暂时不在时，偏好保留。推荐图标始终跟着当前选中的主题。替换主题或计算颜色时，先保留上一帧。过期的任务不能覆盖新主题；新结果要校验通过才生效。

## 构建与安装

插件可以声明 `prepareResources` 模块。模块导出 `prepareResources(outDir)`，返回生成资源的相对路径。构建器先打包入口和它的依赖，再在单独的进程里执行。生成结果不写回源码。平常的 dev 和 build 会先准备插件，再验证默认主题的静态颜色并生成首屏 CSS，然后才构建宿主和 PWA。默认颜色无效时，构建失败。`vp run theme:generate` 用来明确更新源码里的快照。

首屏 CSS 来自默认主题插件。运行时的主题接上之后，这份 CSS 就不再使用。浏览器的主题色和 PWA 的配色从语义颜色生成。只有 JSON 的主题直接注册。ESM 和 JSON 都有时，只注册 ESM。主题激活之后，宿主核对插件归属、主题 ID，以及和静态颜色是否一致。不一致就回滚。

构建由宿主入口统一编排。Vite 配置在求值时不构建插件。资源准备、编译和发布分开缓存，并核对输入和产物。开发用的中间件提供目录、Manifest 和带修订号的资源。热更新会跟踪共享代码、CSS 的扫描目录和资源文件。同一个插件的任务串行执行。失败了就不发布；内容和上次一样时，不重复激活。生产环境先发布不会再改的资源，最后才替换 catalog，并留下旧的修订供下载。

生产客户端构建时，会合并宿主实际用到的依赖，以及所有官方插件的许可证片段，并生成发布资源和 PWA 的修订。开发环境的清单按运行时依赖声明生成，所以可能比生产多一些依赖。

## 宿主链接与挂载

可选的 `IHostLinks.getImportUrl()` 返回完整的公开导入入口，或者 `null`。Web 上的入口包含部署 base。分享插件负责载荷和 hash。没有入口时，只输出分享口令。非法 URL 会报错。`encodeShareLink` 显式接收入口，长度估计包含基址。

`ChronosMountable.mount` 只返回 `{ update?(props): void; unmount(): void }`。挂载的出口会核对这个句柄，并按实例清理。卸载时抛错，不阻止后面的挂载。`mount` 抛错之前，插件自己回滚已经产生的副作用；成功返回之后，由宿主负责卸载。

## 取舍

主题可以换成别的配色算法，但默认主题必须同时给出静态的首屏资源，并且和运行时注册的贡献一致。项目直接维护现在这套接口，不保留旧的 M3 导出、把函数当作挂载返回值的写法，或旧的资源准备签名。
