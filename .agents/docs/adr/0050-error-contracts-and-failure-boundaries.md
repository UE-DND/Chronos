# ADR 0050：错误契约与失败边界

- 日期：2026-11-11

## 决策

记录不存在，和读取失败，是两回事。只有记录确实不存在时才返回 `null`。数据库访问失败、JSON 或二进制解码失败、映射失败，都传给调用方。核心启动会并行读取本地课表列表和当前课表，全部成功之后才提交选择和状态。读取失败时，不切换当前课表。清空和选择写入共用一条串行队列，迟到的读取不能把已经清空的状态恢复回来。

配置修改串行写入，成功之后才发布内存里的配置和事件。课表写入提交之后，发布这份可以信任的快照。后面的刷新、选中或派生工作如果失败，用 `timetable:followUpFailed` 报告原来的原因；已经提交的结果仍然保留。清空会使还没发布的保存结果，以及后续的选中工作失效，迟到的结果不能把旧列表恢复回来。删除继续区分提交前失败和提交后失败。提交之后又失败时，结果里带着 `cause`。`timetable:updated` 明确允许课表为 `null`。

预期中的业务失败，沿同一条调用链使用固定的结果或已知异常，到用户操作的边界再换成文案。宿主根据已有的 `ImportSlotError` 的名称、消息和合法种类识别业务错误，这样插件单独打包之后，构造器身份不同也能认出来。网络适配只转换和重试已经识别出的网络错误。JSON 和 Schema 解析只转换已知的格式错误。未知的程序异常保留原来的身份和原因链，一直传到宿主的执行边界。服务端边界继续使用现有的 `Upstream` 响应。日志保留能用来定位的原因链和堆栈，不输出凭据，也不输出上游的敏感消息。

课程查询要分清还在加载、已经成功和已经失败。失败时可以保留旧快照，但必须标明失败，并提供重试。着色这类可选能力单独降级。插件在同步挂载、更新，以及 Svelte 渲染或效果里失败时，都在插件界面这一层报告。失败的子树或实例停下来，用户明确重新加载时再建立新实例。普通的异步任务和事件失败，由各自的控制器负责。

## 取舍

保留事务、提交之后的补偿、有上限的网络重试、过期的异步结果作废、资源清理，以及写明了条件的缓存降级。不新增一套通用异常框架，也不要求整个仓库只用一种结果类型。失败怎么传、能不能恢复，以这个模块自己的业务含义为准。不能用空数据、默认配置或一张正常的空白界面掩盖失败。

数据库结构，以及分享、插件和原生更新的线协议都不改。变的是这些公共契约：存储读取失败怎么表示、核心启动怎样才算成功、事件里的课表可以为空，以及删除之后的失败结果长什么样。
