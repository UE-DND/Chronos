# ADR 0050：错误契约与失败边界

- 日期：2026-11-11

## 决策

存储缺失与读取失败分别表达。仅不存在的记录返回 `null`；数据库访问、JSON 或二进制解码及映射错误传播给调用者。核心启动并行读取本地列表与活动课表，在所有读取成功后提交选择与状态；读取失败不切换活动课表。清空与选择写入共用串行队列，迟到读取不得恢复已清空的状态。

配置修改串行写入，成功后发布内存配置和事件。课表写入提交后发布可信快照；后续刷新、选中或派生工作失败，通过 `timetable:followUpFailed` 报告原始原因，操作仍保留已提交结果。清空使待发布的保存结果和后续选中工作失效，迟到结果不得恢复旧列表。删除继续区分提交前失败与提交后失败，其后续失败结果携带 `cause`。`timetable:updated` 明确允许 `null`。

预期业务失败沿同一调用链使用固定的结果或已知异常，在用户操作边界映射文案。宿主依据既有 `ImportSlotError` 的名称、消息及合法种类识别业务错误，支持插件独立打包后的构造器身份差异。网络适配只转换及重试已识别的网络错误；JSON 和 Schema 解析只转换已知格式错误。未知程序异常保留身份和原因链，传播到宿主执行边界。服务端边界继续使用现有 `Upstream` 响应，日志保留可用于定位的原因链与堆栈，并避免输出凭据和上游敏感消息。

课程查询区分加载、成功和失败，失败可以保留旧快照，但明确标记并提供重试。着色等可选能力独立降级。插件同步挂载、更新以及 Svelte 渲染或效果失败都在插件界面边界报告；失败子树或实例停止运行，用户显式重载建立新实例。普通异步任务与事件失败由各控制器负责。

## 取舍

保留事务、提交后补偿、有界网络重试、异步过期失效、资源清理与明确的缓存降级。不新增通用异常框架，也不要求全仓统一为一种结果类型。失败传播和恢复以所属模块的业务含义为准，不能用空数据、默认配置或正常空白界面掩盖失败。

数据库结构和分享、插件及原生更新线协议不变。改变的是存储读取失败、核心启动成功边界、事件可空类型与删除后续失败结果的公共契约。
