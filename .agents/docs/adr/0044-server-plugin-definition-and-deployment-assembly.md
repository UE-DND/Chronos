# ADR 0044：服务端插件定义与部署配置

- 日期：2026-09-20
- 修订：ADR 0042 的服务端模块、代理 action 和域名归属

## 决策

官方插件包通过 `./server` 导出服务端处理函数，并通过无副作用的 `./server/definition` 导出 `serverDefinition`。定义包含 `pluginId`、单个代理 `action` 和 `domains`。客户端调用和服务端 `serverManifest` 引用同一份定义。构建器会从官方目录定位插件包，读取包名和导出，校验定义，并生成静态服务端导入和客户端可用 action 列表。正式和开发环境的市场 manifest 都会根据该定义生成 `optionalServerCapabilities`。缺少声明或声明不一致时，构建会失败。

部署配置只声明要启用的插件 ID。启用的服务端模块作为宿主构建依赖打入发行包。未启用的模块不会进入生成的服务端 loader。没有启用插件时，不生成代理路由。客户端安装或卸载不会改变服务端部署。域名用于插件申报和审查，不会限制服务端的出站网络请求。

## 影响

新增服务端插件时，要将它加入官方插件目录，并提供两个包导出。目标宿主还要声明构建依赖和部署白名单。宿主不需要填写插件的服务端导入路径、action 或域名。现有 `/api/plugins/{pluginId}/{action}` 和 `PluginServerResponse` 线协议保持不变。本决策不增加运行时上传或动态部署服务端代码的能力。
