# ADR 0044：服务端插件定义与部署配置

- 日期：2026-09-20
- 修订：ADR 0042 的服务端模块、代理 action 和域名归属

## 决策

官方插件包从 `./server` 导出服务端处理函数，从没有副作用的 `./server/definition` 导出 `serverDefinition`。定义里有 `pluginId`、一个代理 `action` 和 `domains`。客户端调用和服务端的 `serverManifest` 用的是同一份定义。构建器从官方目录找到插件包，读取包名和导出，核对定义，然后生成静态的服务端导入，以及客户端可以用的 action 列表。正式环境和开发环境的市场 manifest，都会按这个定义生成 `optionalServerCapabilities`。缺了声明，或者声明对不上，构建就失败。

部署配置只列出要启用的插件 ID。启用了的服务端模块作为宿主的构建依赖打进发行包。没启用的模块不会进生成出来的服务端 loader。一个插件都没启用时，不生成代理路由。用户在客户端安装或卸载，不会改变服务端部署了什么。域名用来申报和审查，不限制服务端向外发出的请求。

## 影响

新增服务端插件时，把它放进官方插件目录，并提供上面两个包导出。目标宿主还要声明构建依赖和部署白名单。宿主不用填写插件的服务端导入路径、action 或域名。现有的 `/api/plugins/{pluginId}/{action}` 和 `PluginServerResponse` 线协议保持不变。这个决定不增加在运行时上传或动态部署服务端代码的能力。
