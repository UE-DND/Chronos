# ADR 0047：宿主更新与插件安装事务

- 日期：2026-09-26
- 修订：ADR 0030、0035、0042、0045 的升级与缓存行为

## 宿主身份与发布

`HostBuildIdentity` 包含发布版本、源码提交、Profile、部署配置、平台和确定性构建摘要。摘要来自标签源码与生效配置，构建时间不参与身份。

网站 `/version.json` 描述当前部署；Android `/android/stable.json` 描述已发布且所有 Profile APK 就绪的最高稳定版本，两者独立。

Android feed 固定 APK URL、SHA-256、字节数、包名、versionCode、签名证书和 Profile。客户端读取实际安装包的签名与版本，匹配自身 Profile 后才使用更新地址。

所有发行包使用相同包名与正式签名；常规更新保持 Profile，用户手动安装另一 Profile 是显式切换，保留课表及配置。

CI 先发布不可变的官方插件目录并执行 HTTP 验证。Vercel 发布与 APK 发布各自完成。APK 校验签名及资源后上传到 draft Release；三个 Profile 全部上传成功才公开 Release。

随后在产物分支保存 Android 发布记录，选择最高 versionCode 推进 stable feed，并复用已构建的网站二次部署 Pages。网站回滚保留历史插件与原 Android stable。

发布资产不使用覆盖上传；重试优先复用已上传且身份一致的签名 APK，缺失或冲突明确失败。

## 插件与数据

安装集合保存在现有 `pluginData` 表，结构版本仍为 `1`。写操作在 IndexedDB 事务中读取最新行并合并；集合修订号、单插件修订号、宿主代次防止跨窗口覆盖、下载结束后恢复已卸载插件、旧窗口覆盖新宿主结果。

未来宿主的准备快照与当前安装集合分开，下载准备期间不加载未来代码。BroadcastChannel 通知其他窗口刷新运行时；身份改变时销毁旧引擎并重载。

官方插件只能从官方命名空间安装，保留官方 ID。

重置用户数据保留 PWA 页面壳和预缓存代码，与 APK 内置资产一样用于离线恢复必需功能；课表、插件安装记录与数据、图片及偏好仍清空。

页面壳缓存丢失后只下载并校验当前 Worker 的固定构建资源，不混用其他版本。启动前检查缓存版本与各资源摘要；不兼容的缓存保留记录与数据但不执行。

第三方插件不要求新增 Manifest 字段，安装记录保存用户确认的宿主版本；宿主版本变化后需手动重新启用。

## Web

用户确认更新后，先下载所有已安装可选官方插件的目标版本，包括禁用插件。新 Profile 的必需插件由新宿主预缓存提供。

资产校验完成后，事务重新核对安装集合修订号，保存完整快照并短暂禁止插件管理写入，然后安装精确匹配目标 buildId 的 Worker。

Worker `install` 门禁在已有 active Worker 时要求匹配且有效的准备快照；自动更新无授权则安装失败，保留旧 Worker。

成功下载的 Worker 延长写入门禁至新宿主接管，避免关闭最后窗口绕过准备。

准备中断且不存在 installing/waiting Worker 时释放门禁；安装未完成的授权有超时。已有 waiting Worker 的准备快照会继续保留。新宿主启动一次性采用匹配快照，保留禁用状态。

每个构建用 SvelteKit 的备用页面（fallback） 生成独立的 SPA 页面壳和 `_app/env.js` 快照。Worker 安装时校验并缓存两者，导航始终取控制该页面的 Worker 所属页面壳，保留路径、查询参数和深链接；API、版本和插件请求不使用页面壳。

所有窗口监听 `controllerchange`，后台窗口回到前台时再次核对 Worker 身份；接管时销毁旧引擎并强制刷新，不另加未保存编辑确认。

## APK

先更新 APK。新版启动时从随包资源恢复必需插件，以课表可用为优先；可选官方插件若版本不符，保留启用意图、配置、数据和主题选择，暂不执行。

后台逐个下载、校验、替换，再按原启用意图激活。失败不阻塞课表，在联网、回到前台或手动重试时继续，重复请求合并。同宿主替换失败才允许回滚已运行的兼容插件；不恢复旧宿主代码。

## Profile 与服务端

CQUT 离线 Profile 禁止 `source-cqut/preview`，构建排除对应 Web 和原生 处理器，HTTP 适配器也拒绝直接调用；HTML 导入及插件市场联网保持可用。能力显示读取实际 HTTP 服务的支持情况。

Web 插件请求携带宿主版本和 Profile。服务器在加载处理器前验证，版本或 Profile 不匹配返回 HTTP 426 / `UpdateRequired`，客户端提示更新，不维护历史处理器。

开发结构失效时由开发者手动清空并重新导入，不新增迁移链或启动时清空逻辑。

首次采用本方案须发布新版本。旧开发客户端没有准备协议，不能通过新 Worker 门禁；按未发布阶段约定，先备份课表，再手动清空站点或应用数据并重新导入，之后的更新使用本协议。不为旧安装结构或旧 Worker 新增兼容分支。
