# ADR 0047：宿主更新与插件安装事务

- 日期：2026-09-26
- 修订：ADR 0030、0035、0042、0045 的升级与缓存行为

2026-11-13 修订：插件实例、存储、日历贡献及公共界面的当前契约见 [ADR 0052](0052-plugin-activation-and-calendar-contributions.md)。本记录保留原决策的背景；与后续契约冲突的接口不再适用。

## 宿主身份与发布

`HostBuildIdentity` 包括发布版本、源码提交、Profile、部署配置、平台，以及确定性的构建摘要。摘要按标签上的源码和实际生效的配置计算，不包含构建时间。

网站上的 `/version.json` 描述当前这次部署。Android 的 `/android/stable.json` 描述已经发布、并且所有 Profile 的 APK 都已就绪的最高稳定版本。两份文件彼此独立，不能互相代替。

Android feed 固定 APK 的 URL、SHA-256、字节数、包名、versionCode、签名证书和 Profile。客户端先读取本机安装包的签名和版本，只有 Profile 也匹配时，才使用其中的更新地址。

各发行包使用相同的包名和正式签名。常规更新保持原来的 Profile。用户另行安装另一个 Profile，是一次明确的切换，课表和配置会保留。

发布时先上传不会再改的官方插件目录，并做 HTTP 验证。Vercel 发布和 APK 发布各自完成。APK 在校验签名和资源之后上传到 draft Release；三个 Profile 都上传成功，才把 Release 公开。

接着把 Android 的发布记录写到产物分支，按最高的 versionCode 推进 stable feed，并用已经构建好的网站再部署一次 Pages。网站回滚时，历史插件目录和原来的 Android stable 都保留。

发布资产不覆盖上传。重试时优先复用已经上传、且身份一致的签名 APK。文件缺失或身份冲突，就明确失败。

## 插件与数据

安装集合的元数据放在 `pluginData` 表。JS、CSS、配色 JSON 和图标 JSON 的正文放在 `pluginResources` 表。安装记录和更新准备快照只保存不会再改的资源引用。

数据库和结构版本仍是 `1`。开发时如果结构变了，手动清空站点或应用数据，再重新导入。不增加迁移，也不为旧结构留兼容分支。写的时候在 IndexedDB 事务里读最新的一行再合并。资源写入、元数据变更，以及删除已经没有引用的资源，放在同一个事务里。普通的状态修改不重写资源正文。

哪些资源留下，由当前安装集合和准备快照一起决定。取消准备、采用新版本、卸载和用户重置，都会删除失去引用的资源。集合修订号、单个插件的修订号和宿主代次，用来避免跨窗口互相覆盖、下载结束后把已卸载的插件装回来，以及旧窗口覆盖新宿主的结果。

正在准备的未来宿主，和当前的安装集合分开保存。下载和准备期间不加载未来版本的代码。其他窗口通过 `BroadcastChannel` 刷新运行时。身份变了就销毁旧引擎，并重新加载。

官方插件只能从官方命名空间安装，并保留官方 ID。

重置用户数据时，保留 PWA 的页面壳和预缓存代码。它们和 APK 里的内置资源一样，用来在离线时恢复必需功能。同时保留当前 Profile、当前宿主版本必需的预装插件记录，以及这些插件引用的主题图片。课表、额外安装的插件、全部插件用户数据、个人图片和偏好会被清除，然后重新套用 Profile 的默认设置。IndexedDB 里的筛选和删除在同一个事务中完成。更新还在准备时，拒绝重置。

页面壳缓存丢失后，只下载并校验当前 Worker 那一份构建的资源，不和其他版本混用。启动前检查缓存版本和各项资源的摘要。缓存不一致时，保留记录和数据，但不执行里面的代码。

第三方插件不需要新增 Manifest 字段。安装记录保存用户确认过的宿主版本。宿主版本变化之后，要用户自己重新启用。

## Web

用户确认更新之后，先下载已经安装的全部可选官方插件的目标版本，包括当前禁用的插件。新 Profile 必需的插件，由新宿主的预缓存提供。

资源校验通过后，在事务里再核对一次安装集合的修订号，保存完整快照，并短暂禁止写入插件管理数据，然后安装与目标 buildId 完全一致的 Worker。

已经有 active Worker 时，Worker 的 `install` 门禁要求一份匹配、并且仍然有效的准备快照。没有用户授权的自动更新会安装失败，旧 Worker 继续保留。

下载成功的 Worker 会把写入门禁延长到新宿主接管，避免关掉最后一个窗口就绕过准备。准备中断，并且没有 installing 或 waiting 的 Worker 时，释放门禁。还没完成的安装授权有超时。已经在 waiting 的 Worker，它的准备快照继续保留。

新宿主启动时，一次性采用匹配的快照，并保留插件原来的禁用状态。

每个构建用 SvelteKit 的备用页面（fallback）生成自己的 SPA 页面壳和 `_app/env.js` 快照。Worker 安装时校验并缓存这两份文件。导航始终使用正在控制该页面的 Worker 所属的页面壳，并保留路径、查询参数和深链接。API、版本和插件请求不走页面壳。

所有窗口监听 `controllerchange`。留在后台的窗口回到前台时，再核对一次 Worker 身份。接管时销毁旧引擎并强制刷新，不再额外询问未保存的编辑。

## APK

应用内的 APK 下载、校验和安装见 [ADR 0048](0048-android-native-self-update.md)。

用户确认更新之后，先下载并校验已经安装的全部可选官方插件的固定目标版本，再开始下载和安装 APK。必需插件来自新 APK 里的本地资源，不在线重复下载。任何一个插件准备失败，就停止这次更新，旧应用和数据仍然可用。准备期间不执行未来版本的插件代码。

Android 快照里的 `until: null` 表示这份授权跟着原生任务的生命周期走，不能套用 Web 那边的短时授权。准备提交时核对安装集合的修订号，然后禁止安装、卸载和兼容性确认这类会改集合的写入。课表编辑和当前正在运行的插件不受影响。

原生任务会把准备 token 和固定的目标描述存下来。进行中的任务保留匹配的快照。失败、取消，或已经没有关联任务时，按 token 释放门禁，并清理暂存文件。启动和回到前台时，再核对实际任务。新版本启动时，一次性采用 buildId 和修订号都匹配的快照，然后从安装包里的资源恢复必需插件。

Android 不再在启动、联网或回到前台时，自动下载不兼容的插件。手动覆盖安装，或者缓存不见了，会保留记录、配置、数据和主题选择，暂停不兼容的代码，并给出明确的重试。第三方插件仍要用户自己确认兼容。

## Profile 与服务端

CQUT 离线 Profile 禁止 `source-cqut/preview`。构建会排除对应的 Web 处理器和原生处理器，HTTP 适配器也会拒绝直接调用。HTML 导入和插件市场的联网仍然可用。界面上显示的能力，以实际 HTTP 服务的支持情况为准。

Web 上的插件请求会带上宿主版本和 Profile。服务器在加载处理器之前先验证。版本或 Profile 不一致时，返回 HTTP 426 和 `UpdateRequired`。客户端提示用户更新，不为旧版本继续保留处理器。

开发中的数据结构失效时，由开发者手动清空再重新导入。不增加迁移，也不在启动时自动清空。约定见 [CONTRIBUTING.md](../../../CONTRIBUTING.md#未发布阶段的数据约定)。

第一次采用这套准备协议时，需要发布一个新版本。更早的开发客户端没有准备协议，过不了新 Worker 的门禁。按上面的未发布约定，先备份课表，再手动清空站点或应用数据并重新导入；之后的更新走本协议。不为旧的安装结构或旧 Worker 增加兼容分支。

同源部署用部署根路径生成稳定的存储命名空间，覆盖数据库、Web Storage、Cache Storage、语言 Cookie、通知锁和跨窗口消息。版本和 Profile 不放进命名空间，这样在原路径更新时数据还在。根路径变了，就会换一份数据空间，旧数据由开发者手动清理。浏览器给不给持久存储、配额有多少，仍按来源由浏览器决定。
