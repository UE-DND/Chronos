# ADR 0049：有界的宿主启动与首屏衔接

- 日期：2026-10-12

## 决策

宿主启动状态统一记录核心准备、插件恢复、页面显示和失败原因。核心准备保留本地数据、默认主题验证和宿主更新事务保护，25 秒内未完成即明确失败。Android 更新器状态和事件恢复共用 3 秒等待上限；状态未知时不能继续写入宿主代次或释放更新锁。

核心准备完成后挂载页面外壳；插件恢复通过普通任务启动，先恢复兼容的本地安装缓存，再补装缺失的预安装项。完整初始化失败向调用者传播，失败尝试在本次会话内不自动重试。插件恢复等待上限为 10 秒，超时后允许显式进入课表；之后的迟到注册不得覆盖用户选页。更新和恢复初始状态要求完整启动成功。

正常启动仍在插件恢复完成后选择声明的默认首页。不先显示课表再跳转。非关键页面预热可以使用带 1000 毫秒超时的空闲回调，关键启动不得依赖空闲回调。

Android 原生启动屏在本地主文档或错误页加载完成后关闭，并有 8 秒兜底及 Activity 销毁清理。网页启动遮罩在加载、失败或目标页面内容已挂载，经 Svelte 更新和一次动画帧衔接后关闭，避免裸露空白背景。

## 超时与验证边界

等待超时不等于取消底层插件或原生工作。不重复启动仍在执行的操作，不接受迟到结果改变失败状态；重试通过页面重载建立新会话。已有安装记录、更新协议和数据库结构保持不变。

阶段失败使用现有错误捕获、回放和日志插件，阶段完成通过 Performance 标记记录，不增加持久化日志库。浏览器受控调度测试和 Android 真机冷启动验证分别报告；模拟挂起空闲回调不能证明特定 WebView 的真实故障原因。
