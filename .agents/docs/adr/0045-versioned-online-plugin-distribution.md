# ADR 0045：按宿主版本在线分发官方插件

- 日期：2026-09-26
- 修订：ADR 0030 / 0042 的资源发布与目录选择

## 决策

GitHub Pages 是唯一的官方在线分发入口，目录为 `https://ue-dnd.github.io/Chronos/plugins/releases/<宿主版本>/catalog.json`。官方插件仍和宿主用同一个版本构建。Release 只发布应用安装包，不再另给一套插件下载入口。源码继续放在这个 Monorepo 里。

完整市场输出到 `dist/plugin-market`。宿主构建会清理旧的静态资源，只把当前 Profile 必需的插件复制到 `static/official-plugins`。目录和 Manifest 使用相对地址。内置资源和远程资源是同一份字节、同一份摘要。默认主题的首屏 CSS、资源校验和卸载保护，沿用已有契约。安装记录、跨窗口事务和回滚范围，由 [ADR 0047](0047-host-update-transactions.md) 再作修订。

Profile 补装和必需插件的版本同步，读内置的精简目录。商店，以及同步已经安装的可选官方插件，读固定宿主版本的远程完整目录。来源按 origin、路径边界和插件 ID 识别。远程的官方 Manifest 和宿主版本不一致时，拒绝安装。用外部 Manifest URL 安装仍然保留，但不参与官方的版本同步。宿主版本变了之后，第三方插件要用户自己重新启用。开发环境使用本地的完整市场和热更新。

PWA 只预缓存本地必需的资源。已经安装的插件从数据库恢复，不另开一条把远程资源持久化下来的路径。没有网络时，可以启动内置功能，也可以使用已经缓存的插件，但不能安装新的可选插件。没有可用的默认主题时，启动仍然明确失败。

## 发布

正式目录只从 `vX.Y.Z` 标签发布，标签必须和宿主版本一致。产物分支 `codex/plugin-dist` 保存各版本的快照、源码提交和文件摘要，不保存源码。源码分支不提交生成物。已经发布的版本只允许用相同提交、相同产物重试，不覆盖，也不删除历史版本，也不提供 `latest`。

Pages 的 CI 把历史目录和当前 default Profile 的网站合在一起，一次部署所有版本。上线时检查当前版本，以及一个历史版本的目录、Manifest 和一份有代表性的资源。Vercel 在 Pages 验证成功之后发布。APK 发布之前，也必须确认对应的插件目录已经上线。回滚网站时，全部历史插件目录仍然保留。

## 边界

数据库、Catalog 和线格式的版本维持 `1`。直接维护现在的结构，不增加旧目录别名，也不为数据补迁移。开发数据不兼容时手动清空。第一次迁到这套分发方式时发布新版本，不重做旧标签。旧 APK 继续使用它自己随包带的资源。

原生代码和服务端部署仍跟着各自的宿主构建走。下载一份 ESM，不会给安装包添上新的 Capacitor 原生能力。插件和宿主在同一个进程里执行，没有沙箱。SHA-256 只校验完整性，不证明来源可信。
